# Frontend contract, version 0.1

The backend is a browser-facing HTTP service. The frontend may be built independently. Use `POST /api/research/stream` for the main experience; `POST /api/research` is convenient for non-streaming clients and tests.

Use [sample-response.json](sample-response.json) to build the interface before live API keys are available. It is **synthetic test data**, not an actual research result.

## User actions

1. Enter a research question (8–1000 characters) and start a run.
2. Read progress events while the agent plans, searches, checks coverage, drafts, and verifies.
3. Read the answer and inspect each claim's status and citations.
4. Open a cited source URL and compare its quoted passage with the claim.
5. See evidence gaps or a visible error if research cannot finish.

The frontend should not invent citations or infer a positive verdict from a successful HTTP response. Use the returned `status` and each claim's `status`.

## Request

`POST /api/research/stream` or `POST /api/research`

```json
{"question":"Does this product support exporting data in its latest version?"}
```

## Streaming events

The streaming endpoint uses `text/event-stream` over a POST request. Use `fetch()` and parse the event stream; native `EventSource` only makes GET requests.

`progress` contains `stage`, `detail`, `queries`, `search_rounds`, and `source_count`. Stages are `plan`, `search`, `assess`, `draft`, and `verify`. The final `result` event contains the full result object. An `error` event contains `message` and `type`; it should be shown as a failed run, not as a research conclusion.

## Result shape

```json
{
  "question": "Does this product support exporting data?",
  "answer": "根据本次检索，... [S1]。",
  "claims": [
    {
      "text": "The product supports exports.",
      "status": "supported",
      "citations": [{"source_id": "S1", "quote": "supports exports"}],
      "note": "The quoted documentation directly supports this statement."
    }
  ],
  "sources": [
    {
      "id": "S1",
      "title": "Product documentation",
      "url": "https://example.org/docs",
      "query": "product export documentation",
      "snippet": "The product supports exports.",
      "retrieved_at": "2026-11-07T12:00:00Z",
      "published_at": null
    }
  ],
  "gaps": [],
  "trace": [{"stage": "plan", "detail": "Prepared 2 searches", "queries": ["product export documentation", "product export limitations"]}],
  "search_rounds": 2,
  "status": "completed"
}
```

Claim status values: `supported`, `disputed`, `insufficient`. Run status values: `completed`, `partial`, `insufficient_evidence`. `partial` means the answer has supported claims but some research gaps or unverified claims remain.

`sources` intentionally exposes a short snippet rather than the complete scraped page. The citation's `quote` is the exact passage captured during research. `source_id` links each citation to its URL. Dates are UTC when generated by the backend.

## Error states

- HTTP 422: question too short or too long.
- HTTP 503: required API keys or model setting are missing.
- HTTP 502: a non-streaming run failed. The body does not include secrets.
- Streaming `error`: a run failed after the stream began.

The frontend should offer a retry for transient failures. A completed result with `insufficient_evidence` is a valid research outcome and should display its gaps and sources.

## CORS

Default allowed frontend origins: `http://localhost:3000` and `http://localhost:5173`. Override with a comma-separated `FRONTEND_ORIGINS` environment variable.
